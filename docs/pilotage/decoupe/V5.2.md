# V5.2 — Créer le format d'archive hebdomadaire

## État

La veille hebdomadaire (V5.4) et les tendances mensuelles (V5.1) comparent des archives de la semaine
N à celles de la semaine N-1, mais aucun format commun n'est écrit. Ce lot pose le format et un
modèle vide, rien d'autre : aucune mesure réelle, aucun nom de client, aucun chiffre commercial.
Il est purement documentaire et borné au dossier `docs/marketing/seo/veille/` : c'est le premier lot
confié à Agent Lot dans Conductor pour éprouver la chaîne complète (périmètre, commits par prompt,
validation du push), sans aucun effet sur le site ni sur l'application.

Les prompts P1 à P3 partent un par un depuis Agent Lot. Conductor propose chaque push à la
validation humaine ; il ne lance ni la clôture, ni la PR, ni le déploiement.

Responsable : Youness

### P1 · Décrire le format d'archive hebdomadaire
Durée : 20 min
Fichiers : docs/marketing/seo/veille/FORMAT.md
Sources : docs/pilotage/plan.json (lots V5.1, V5.2, V5.4) · docs/pilotage/seo/BASELINE-2026-10-22.md

Faire :
- créer `docs/marketing/seo/veille/FORMAT.md` et y décrire l'arborescence `docs/marketing/seo/veille/YYYY-MM-DD/`, la date étant celle du relevé en heure de Paris
- lister les cinq fichiers obligatoires d'une archive — `donnees-brutes.md`, `synthese.md`, `changements.md`, `sources.md`, `recommandations.md` — avec le rôle de chacun en une phrase
- fixer les règles : chaque fait porte un niveau de preuve MESURÉ, OBSERVÉ, INFÉRÉ ou À CONFIRMER ; chaque source porte une URL, une date de consultation et une fraîcheur ; une valeur absente s'écrit « indisponible » ; aucune donnée personnelle, aucun cookie, jeton ou export de compte
- décrire la comparaison de la semaine N à la semaine N-1 : mêmes requêtes figées, mêmes colonnes, mêmes unités

Test : `node scripts/lot.mjs V5.2`
Fini quand : `FORMAT.md` décrit les cinq fichiers, les quatre niveaux de preuve et la règle de comparaison N/N-1
Hors périmètre : créer le modèle, écrire une archive réelle, modifier le site, le plan ou un autre dossier que `veille/`

### P2 · Créer le modèle vide d'archive
Durée : 25 min
Fichiers : docs/marketing/seo/veille/_modele/donnees-brutes.md · docs/marketing/seo/veille/_modele/synthese.md · docs/marketing/seo/veille/_modele/changements.md · docs/marketing/seo/veille/_modele/sources.md · docs/marketing/seo/veille/_modele/recommandations.md
Sources : docs/marketing/seo/veille/FORMAT.md

Faire :
- créer les cinq fichiers du modèle dans `docs/marketing/seo/veille/_modele/`, chacun avec son titre et les champs décrits dans `FORMAT.md`
- `donnees-brutes.md` : un tableau requête, moteur, date, résultat, preuve, niveau de preuve
- `synthese.md` : cinq lignes au plus et le niveau de preuve de chaque ligne
- `changements.md` : un tableau semaine N-1, semaine N, écart
- `sources.md` : un tableau URL, date de consultation, fraîcheur
- `recommandations.md` : trois recommandations au plus, chacune avec impact, risque et preuve
- remplir les champs avec des repères `<à renseigner>` uniquement : aucune valeur, aucun exemple chiffré

Test : `node scripts/lot.mjs V5.2`
Fini quand : les cinq fichiers existent, reprennent les champs de `FORMAT.md` et ne contiennent aucune valeur réelle
Hors périmètre : remplir une archive, créer un dossier daté, écrire un script
